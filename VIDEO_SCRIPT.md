# Dexterity — two-minute submission video

**Story:** a builder trying to finish before the hackathon deadline. Stay on screen for the whole video; narration and the real voice commands carry the story. The deadline opening is a scenario, not a claim about how long a task actually took.

## 0:00–0:12 · The moment everyone recognises

**Show:** your video editor, then the application form. Two quick cuts. No slide deck.

**Say:** “Five minutes to the deadline. Your demo needs fixing, the application is still empty, and there’s a button you cannot find. You need someone beside you who can see what you’re seeing.”

## 0:12–0:23 · Meet the buddy

**Show:** move the cursor. Let the companion follow. Hold Ctrl and show the listening card once.

**Say:** “This is Dexterity. It lives beside your cursor. Hold Ctrl, say what you need, and it uses the screen you’re already working on.”

## 0:23–0:50 · Fix the demo

**Show:** an actual editor screen where a teaching request succeeds. Resolve’s Color page is a strong choice if rehearsed successfully.

**Say to Dexterity:** “This clip looks too dark. Teach me the first thing to change.”

**Show:** the actual lesson, then a marker only if one appears correctly. Follow the instruction. Leave the result visible long enough to read.

**Say:** “I don’t need a whole course right now. I need the next step on this screen. Dexterity gives me that step, and I can ask it to check again when I’m ready.”

## 0:50–1:08 · Get past the confusing bit

**Show:** a word or phrase in the application instructions. Highlight it and press Ctrl + Shift + E. Use its real explanation.

**Say:** “Next, something in the application trips me up. Highlight it. Ask. The explanation appears right here, with the surrounding text for context. I can keep going.”

## 1:08–1:38 · Finish the paperwork

**Show:** the existing Chrome window containing your rehearsed, owned sample form. Use only sample details.

**Say to Dexterity:** “Fill this form with name Alex Builder and email alex@example.test. Let me review before submitting.”

**Show:** actual fields changing. Keep enough footage to see which fields changed. Show the real approval surface if the run reaches it; do not substitute a static preview. Only approve a submission to your owned local test form.

**Say:** “Same browser. Same session. I give it the details; it handles the typing. It checks the screen after each action. Before submitting, it stops for my approval.”

## 1:38–1:52 · Give the technical audience one useful detail

**Show:** a brief actual task log, then the companion back beside the cursor.

**Say:** “Underneath, a coordinator plans, one operator acts, and a verifier checks the result. Eight actions maximum. If the screen stops changing, it hands the task back.”

## 1:52–2:00 · The line to remember

**Show:** companion beside the app, then Dexterity and the repository address.

**Say:** “The cursor already goes everywhere you work. Now your assistant comes with it. Dexterity.”

## Recording decisions

- Record three successful screen clips, then record the narration once. No face camera, intro animation or settings tour is needed.
- Cut provider waiting time; put “wait shortened” on the cut. Do not speed up the whole video or imply edited footage is real-time performance.
- Let the actual answers and results speak. Never add a fabricated AI response, marker, filled field or success message.
- If Resolve cannot produce a useful real take, use a successfully rehearsed teaching task in another app and change the spoken request to match. A diagram or README preview is not replacement footage of a working agent.
- The latest EXE remains blocked on this PC. Record on an approved working build, or use existing genuine footage clearly labeled with its build. A revised live form approval handoff still needs verification. If those recordings are unavailable, this script is a recording plan, not a completed demo.
